# 今日運彩總覽

一頁看完今日賽事、盤口、傷兵、火燙／冰冷球員、球隊近況、相關新聞與規則式建議。
純靜態網站，零主機費用，資料由 GitHub Actions 每小時自動更新。

## 架構

```
.（repo 根目錄）
├── index.html / style.css / app.js   網頁（讀 data/today.json）
├── data/today.json                   排程產生的資料（自動 commit）
├── data/sample.json                  本機測試用的範例資料
└── pipeline/
    ├── fetch.py                      抓資料 + 規則式建議
    ├── taiwan_odds.py                玩運彩盤口頁解析與配對
    ├── playsport.py                  歐籃、日籃：以玩運彩為主幹的賽事與球隊歷史戰績
    ├── euroleague.py / bleague.py    EuroLeague 官方 API、B.LEAGUE 排名頁
    ├── svleague.py                   SV.LEAGUE 日本排球
    ├── newsinj.py                    Google 新聞傷兵
    ├── elreport.py                   歐籃傷兵報告文章（解 Google 轉址、抓內文）
    ├── players.py                    球員層級：缺陣影響幾分、主力名單
    ├── story.py                      白話分析段落
    ├── names_zh.py                   球隊中文名、狀態中文
    ├── probe_playsport.py            探路用（印網頁結構到 log，平常不跑）
    └── make_sample.py                產生範例資料
.github/workflows/sports-data.yml     每小時排程
```

## 資料來源（全部免費、不用 key）

| 球種 | 賽程、比分、盤口 | 隊徽、排名、近況 | 傷兵 |
|---|---|---|---|
| NBA | ESPN 公開接口＋玩運彩台灣盤 | ESPN（含球員近 5 場火燙／冰冷） | ESPN 傷兵名單 |
| 歐洲籃球（歐冠、歐盃、其他歐洲賽事） | 玩運彩 allianceid 8（台灣盤、國際盤、玩家預測比例） | EuroLeague 官方 API（隊徽、排名、主客分明的賽果、球員場均）；對不上的球隊用玩運彩的歷史戰績 | Google 新聞（英文）＋每輪的傷兵報告文章，用官方球員名單對出誰缺陣、少他差幾分 |
| 日本籃球（B.LEAGUE） | 玩運彩 allianceid 97 | B.LEAGUE 官網排名頁（東西區、主客戰績、近 5 場）、球隊頁的球員平均 | Google 新聞（日文），用官網名單對出缺陣的人、少他差幾分 |
| 日本排球（SV.LEAGUE） | SV.LEAGUE 官網（沒有盤口，勝率依近況粗估） | 官網賽果自己算的排名、球隊選手頁名單 | Google 新聞（日文），對到就標缺陣（隊長、主攻、接應、舉球算主力） |
| 足球、冰球、美足（收在「更多球種」） | ESPN＋玩運彩 | ESPN | ESPN |

沒有官方傷兵名單的聯盟，傷兵區會寫清楚「新聞裡有沒有提到」，不會留白；傷兵快報也會把這些新聞列進去。NBA 的傷兵會查本季（沒有就上季）場均得分與上場時間，換算成大概差幾分讓分；歐籃則從每輪的傷兵報告文章對球員全名。
國際盤是美國莊家的參考值；台灣盤來自玩運彩，抓不到時卡片就不顯示那一塊，不影響其他功能。

## 本機測試

```bash
python3 pipeline/make_sample.py          # 產生 data/sample.json
cd sports && python3 -m http.server 8080        # 開 http://localhost:8080/?data=sample
python3 pipeline/fetch.py                # 真實抓一次（需要能連 ESPN、玩運彩等）
python3 pipeline/fetch.py --leagues eurobasket,jpvolley   # 只抓某幾個聯盟
```

## 建議怎麼算（規則式，不是 AI 預測）

1. 以美國莊家賠率去掉抽水後的勝率為基準。
2. 看好的一方若有主力缺陣（球隊得分／籃板／助攻王在缺陣名單）扣分；對手主力缺陣加分。
3. 近 10 場勝率 7 成以上加分、3 成以下扣分；對手 3 連勝以上扣分。
4. 主力近 5 場比季平均高 15% 以上算「火燙」加分，低 15% 以上算「冰冷」扣分。
5. 調整後勝率達門檻才給「傾向」，否則寫「觀望」。
6. 大小分：兩隊近 5 場平均總分與盤口差距超過門檻才給方向。

免責：這只是整理資料的工具，不保證任何結果。

## 爸爸自己的預測

每場比賽卡片下面和詳細頁都有「押 某隊」（有大小盤的場次還有大分／小分）。開打前可以改、再點一次取消，開打後鎖定；打完自動對答案。
成績單分成「網站的建議」和「我的預測」兩頁：命中率、連中、每場下 100 元是賺是賠、跟網站意見不同時誰對、押主隊／客隊、押熱門／冷門、各聯盟，還有等結果和對過答案的清單。
預測存在手機瀏覽器的 localStorage，不用伺服器；有「備份（下載檔案）」和「匯入備份」。賽果用 `data/results.json`（最近 60 天每一場的比分與收盤線）對答案，所以隔很久才打開也對得到。

## 串關

台灣運彩規則：至少串 2 場、同一場不能串、賠率相乘、全中才有錢；一張至少 100 元、以 10 元為單位；單注中獎超過 5,000 元全額扣 20% 所得稅（領現金再扣 0.4% 印花稅）。

- **今天最穩的 2 串 1**（`pipeline/parlay.py`）：從網站主建議那一邊挑兩場，條件是有台灣運彩賠率、單場賠率至少 1.20、網站估至少五成五會中、期望值不比台灣運彩平常差（85% 以上）、兩場相乘押 100 元至少拿 180 元。挑兩場都中機率最高的。季前賽、沒盤口只靠近況估的不串。大小分要等網站自己的大小分建議對過 20 場、命中 55% 以上才拿來串。第一場開打前 45 分鐘鎖定，打完記在 `history.json` 的 `parlays`，成績單有「推薦的 2 串 1」戰績。
- **每個選項會中的機率**（`suggestion.probs`）：不讓分用盤口勝率，加上網站的調整（傷兵、近況…，還沒證明準不準，只算一半、最多加減 5%）；讓分用盤口的預期分差對台灣的線；大小分只信我們算的總分跟盤口差距的一半。讓分、大小分最多估到七成。
- **串關試算**：把自己押的、還沒開打的場次勾起來，算總賠率、全中機率、中了拿多少、扣稅後多少，可以存成一張串關，打完自動對答案（錯一場就馬上算沒中；取消或延期當賠率 1）。存在 localStorage，備份檔也包含串關。

## 純模型 vs 盤口

每場除了盤口換算的勝率，也記一條「純模型」的答案：只看兩隊實力評分（淨勝分修正對手強弱）、主場優勢、傷兵影響，不看賠率。
成績單裡用命中率和 Brier 分數（越低越準，0.25 等於丟銅板）比較兩條線，另外列出兩邊意見不同的場次誰對得多。資料在 `data/history.json` 的 `model`。

## 老球迷怎麼看（分析的因素）

- **誰會上、會打多久**：讀 ESPN 每個傷兵的備註。分得出「這場輪休」「下一場才休」「上一場沒打」「整季報銷」「會上但限時」。名單寫可以打、但最近 3 場上場時間掉到平常七成五以下，也當成限時（差 20 分以上的大比分不算）。背靠背第二場，看主力上一季背靠背的缺席率，明顯比平常高的就標「背靠背常輪休」。歐籃、日籃從新聞看「帶傷上、限時」的字眼。
- **缺陣影響幾分**：確定不打全算；可能不打乘上不打的機率；限時只算少打的那幾成。
- **近況要扣掉對手強弱**：最近 5 場每場的表現 = 淨勝分 + 對手實力 − 主場優勢。整季 10 場以上才混進評分。連勝都打弱隊、連敗都碰強隊會直接講。
- **剋星**：近兩季例行賽交手，跟「照當時實力該贏幾分」比；玩運彩聯盟看台灣讓分盤過盤。3 場以上幾乎都贏、而且贏得比預期多才算。季前賽交手不算。
- **打法對位（NBA）**：籃板、三分、失誤、節奏，只當說明，不加分數。
- **季前賽**：主力常常輪休，信心最多給「中」，並提醒別下重注。
- **讓它學習**：每個因素都分開算「有算」和「沒算」兩個版本，打完比哪個比較準，成績單會列出每個因素有沒有用。

## 即時比分

- NBA、NHL、足球：網頁直接跟 ESPN 拿，比賽進行中每 30 秒更新。
- 歐洲籃球、日本籃球、日本排球：玩運彩和 SV.LEAGUE 不讓網頁直接抓，所以 `即時比分` 工作流程（`.github/workflows/live-scores.yml`）只在有比賽正在打的時候每分鐘抓一次，寫到 `live` 分支的 `live.json`，網頁每 90 秒讀一次。
